# isaac-save-viewer

This is the source code for the Isaac Save Viewer, a tool to view save completion status for [_The Binding of Isaac: Repentance+_](https://store.steampowered.com/app/3353470/).

This is a personal fork of [Zamiell/isaac-save-viewer](https://github.com/Zamiell/isaac-save-viewer), forked on 2026-11-14 and modified substantially since (see [License](#license)). It is self-hosted as a static website (see [Deploy](#deploy)). The save file is read entirely in the browser and never leaves it.

After you load a save file, it shows:

- your achievements (out of 641), in six groups: character unlocks, character marks, tainted, challenges, daily & online, and misc;
- the items you have touched (out of 720);
- a grid of the Hard completion marks of all 34 characters.

The achievements and items can be shown as a list or as a grid, and filtered to all, locked, or unlocked. These choices, and which sections are collapsed, are remembered in the browser.

- The save file format was reversed by [Blade](https://github.com/bladecoding) using [Kaitai Struct](https://kaitai.io/).
- It is written using [TypeScript](https://www.typescriptlang.org/).
- It uses [esbuild](https://esbuild.github.io/) for bundling.
- Its CSS is hand-written (design tokens in `static/css/`), with a light and dark theme that follows the system or can be switched by hand. It uses the [Rubik](https://fontsource.org/fonts/rubik) font for headings, self-hosted.
- The achievement images are taken from the [Isaac wiki](https://bindingofisaacrebirth.wiki.gg/wiki/Binding_of_Isaac:_Rebirth_Wiki).
- The "items.json" file and collectible images are taken from the [Rebirth Item Tracker](https://github.com/Rchardon/RebirthItemTracker).

## Development

Requires [Node.js](https://nodejs.org/) (LTS).

```sh
npm ci          # Install the dependencies.
npm run dev     # Build, watch for changes, and serve the site at http://localhost:8000/
npm run build   # Build the static site into the "dist" directory.
npm run lint    # Type-check, lint, format-check, and spell-check the project.
npm test        # Run the tests (with Vitest).
```

The data files are generated by scripts:

```sh
npm run data:achievements  # Regenerate "src/data/achievements.json" from the wiki.gg API.
npm run data:marks         # Regenerate "src/data/marks.json" and the mark and character icons.
npm run data:validate      # Check the data files, and count Hard marks in save files.
```

`data:validate` takes save files or folders as arguments. With no arguments, it reads the gitignored `saves/` folder.

- `src/` contains the TypeScript source code. `src/save/` parses a save file into a model without touching the page, and `src/view/` renders that model. `src/kaitai/` contains the save file parser, which is generated from `IsaacSaveFile.ksy` by the Kaitai Struct compiler.
- `static/` contains the HTML, CSS, and images. The build copies it into `dist/`, along with the bundled `main.js` and the font.
- `dist/` is a complete static website that makes no requests to other servers.
- `test/` contains the tests. `test/fixtures/` contains real Repentance+ save files that they read.

## Deploy

The site is published as a Docker image on the GitHub Container Registry (GHCR): `ghcr.io/perumanterola/isaac-save-viewer`. The image builds the site with Node.js and serves `dist/` with [Static Web Server](https://static-web-server.net/) on port 80. It is built for `linux/amd64`.

### Publishing an image

The [Docker workflow](.github/workflows/docker.yml) builds and pushes the image:

- **Publishing a GitHub release** (e.g. `v1.0.0`) pushes the tags `1.0.0`, `1.0`, and `latest`.
- **Running the workflow manually** (Actions → Docker → Run workflow) pushes the tags `edge` and `sha-<short SHA>`.

GHCR packages are private when they are first published. After the first run, either make the package public (GitHub → your profile → Packages → `isaac-save-viewer` → Package settings → Change visibility), or give TrueNAS credentials for GHCR (a personal access token with the `read:packages` scope).

### TrueNAS

1. Go to Apps → Discover Apps → Custom App → Install via YAML.
1. Paste the contents of [`compose.yaml`](compose.yaml). Change the image tag to the version that you published.
1. Open `http://<truenas-ip>:8080/`.

No reverse proxy is needed. The page makes no requests to other servers, and the save file is only read in the browser.

With Docker Compose anywhere else, run `docker compose up -d` in the directory that contains `compose.yaml`.
